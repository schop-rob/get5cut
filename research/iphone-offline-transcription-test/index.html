Controls

  1. Use one iPhone, one iOS build, the same microphone position, and the same source files for every engine.
  2. Download required models before the test. Record device, iOS, 5cut, engine, and model versions.
  3. Enable Airplane Mode before each transcription run and confirm Wi-Fi and Bluetooth are off.
  4. Start from a fresh import for each run. Do not manually correct an engine output.
  5. Export the raw text and measure elapsed transcription time with the same timing rule.
  6. Publish failures and weak results. A network-dependent or failed run is a result, not a reason to omit the engine.

How word error rate is calculated

Word error rate (WER) is the minimum number of substitutions, deletions, and insertions required to transform the engine output into the reference transcript, divided by the number of words in the reference.

WER = (substitutions + deletions + insertions) / reference words

The repository contains a dependency-free calculator at growth_engine/benchmark/compute_wer.py. Before publication, the normalization rules and exact command must be listed here so another person can reproduce each number.

Required publication bundle

  • Both original audio files and manually checked reference transcripts.
  • All eight raw engine outputs: four engines × two samples.
  • WER results, edit counts, elapsed times, and any failed runs.
  • Device, iOS, 5cut, engine, and model versions plus the test date.
  • Normalization rules and the exact calculator command.
  • A limitations section that distinguishes this small, single-speaker test from a general accuracy claim.

Limitations to publish with the results

This will be a two-sample test recorded by one speaker on one device, not a population benchmark. WER can change with microphones, background noise, technical vocabulary, accents, languages, segmentation, punctuation normalization, model versions, and device hardware. The results will describe these files and this setup only.
