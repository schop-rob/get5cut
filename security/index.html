Security

Data handling summary for IT and procurement review. Last updated 28 July 2026, app version 1.2.5.

5cut records and transcribes audio and video entirely on the user's device. There is no 5cut server, no account system, and no cloud processing. Recordings, transcripts and exports never leave the device unless the user exports them somewhere themselves.

Why no DPA is needed

A data processing agreement governs a processor handling personal data on a controller's behalf. 5cut never receives your data, so there is no processing relationship to govern. The developer has no technical ability to access, view, or retain any recording, transcript, or export — not because of a policy commitment, but because no system exists that could receive them.

If your process requires a signed statement to that effect rather than a policy page, contact us and we will provide one.

Where data lives

  • Imported and recorded media, drafts, and transcripts are stored inside the app's iOS sandbox container on the device.
  • Nothing is written to shared storage unless the user explicitly exports it.
  • The container is covered by your device's MDM policy, remote wipe, and encryption posture like any other app.

Encryption at rest, precisely

Two layers apply. Every modern iPhone encrypts its storage in hardware with a key fused into the silicon, which defeats physically extracting the flash. On top of that, iOS Data Protection gives each file a key wrapped by a class key derived in part from the user's device passcode. 5cut's files use:

  • Complete protection for the project database — unreadable whenever the device is locked.
  • Complete until first user authentication for imported and recorded media — unreadable until the user unlocks the device once after a restart. This is also the iOS default for app data.

Two limits worth stating plainly. Data Protection derives its strength from the user having a device passcode; without one, protection falls back to the hardware layer alone — which is why a passcode policy enforced through MDM matters. And it protects a lost or stolen device, not a device that is unlocked in an attacker's hands. Once a user exports a file to Photos or Files, it is governed by that destination's protection, not by 5cut's.

Transcription and speaker identification

All speech processing runs locally using on-device models:

  • Apple SpeechAnalyzer (iOS 26+), using Apple's on-device speech assets.
  • WhisperKit, Parakeet and Qwen3-ASR, running as local Core ML models.
  • Speaker identification uses a local Sortformer model.

Earlier versions could fall back to Apple's server-side speech recognition for language and device combinations without on-device support. That path was removed in version 1.2.5. The engine that could reach a server is gone; every engine listed above runs locally.

The app does declare the iOS Speech Recognition permission. Apple requires that declaration from any app that links its Speech framework, which 5cut does in order to use the on-device transcriber — the declaration identifies which API an app uses, not where the audio goes. If you want to verify the destination rather than the API: put the device in airplane mode after the model has downloaded and transcribe a recording, or watch the device's traffic through a proxy while it transcribes.

Network activity

The app makes outbound requests in exactly two situations, and neither transmits user content:

  • Model downloads. The first time a user selects an engine, its model is downloaded from Hugging Face (or its mirror) or, for Apple's engine, from Apple. This is a one-time download to the device.
  • User-initiated video import. If a user chooses to import a video from a URL, the app fetches that URL.

There are no analytics, crash-reporting, attribution, or advertising SDKs. The app's internal analytics helper compiles to debug-build logging only and is inert in App Store builds.

Third-party components

All are open-source, run locally, and perform inference or utility work only. None transmit user data:

  • WhisperKit (argmaxinc) — local speech recognition
  • FluidAudio (FluidInference) — local speech recognition and speaker diarization
  • swift-transformers, swift-jinja (Hugging Face) — local model tokenisation and templating
  • swift-collections, swift-argument-parser (Apple) — data structures and utilities

Permissions requested

  • Microphone — only while recording in the app.
  • Photo Library — to select videos to edit and to save exports the user requests.
  • Files — when the user imports a file.
  • Speech Recognition — required by Apple for use of its on-device speech engine. Grants access to the local recogniser, not to a network service.

Contacts, location, calendar, and tracking permissions are not requested.

Data export is user-initiated

Users can export transcripts and notes to Apple Notes, Markdown, Anki, Notion or Obsidian, and video to Photos or Files. These are deliberate user actions with a normal iOS share sheet. If your organisation restricts destinations, this is governed by your existing MDM and Managed Open In policies — 5cut adds no independent channel.

What we do not claim

5cut is a small independent app, and it is worth being precise about the limits.

There is no SOC 2 report, no ISO 27001 certification, and no third-party penetration test. Those attest to organisational controls around handling customer data — controls that exist to manage a risk 5cut does not create, because no customer data is received.

There is also no admin console, no central policy enforcement, and no audit log, because there is no account system to attach them to. Deployment and control are handled entirely through Apple Business Manager and your MDM.

Deployment

5cut is distributed through the App Store and can be deployed to managed devices via Apple Business Manager and your MDM. Note that Apple does not permit in-app purchases to be bought in volume — for an organisation-wide licence, contact us about a custom build with the paid features already enabled.
